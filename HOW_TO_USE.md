# Agentic Planner-Worker-Judge Workflow

A **portable, domain-neutral** Cursor workflow for building software with coordinated AI agents.
It splits work into **Planner** (designs), **Workers** (implement), **Judge** (reviews) —
and sizes the loop to the job: **code-loop** and **shape-lite** for daily indie ship,
full plan → design → execute only when scope needs gates.

Everything ships stack-agnostic. You describe your project **once** in `AGENTS.md` (**§0 profile + layers**), run `profile-sync`, and every agent respects which layers exist — FE-only, BE-only, or fullstack without re-editing workflow commands.

## 1. Core idea

| Role | Who | Does | Can edit |
|---|---|---|---|
| **Planner** | `architect-planner` | Shape-lite, brainstorm, ADRs, task breakdown, syncs `AGENTS.md` | `docs/**`, `.cursor/**`, `AGENTS.md` |
| **Workers** | layer-filtered set | Implement inside a narrow scope | only their configured paths |
| **Judge** | `judge-agent` | Read-only review of **plans** and **code** | `docs/reviews/**` |

Key principles:

- **`AGENTS.md §0` is the source of truth** for which layers exist (frontend, backend, database, multi-tenancy, …).
- **Layer off = absent** — plans must not inject DB/tenancy/queue when those layers are off.
- **Right-sized loops** — `/fix`, `/shape-lite`; full gates only when structural.
- **Domain-agnostic** — no product lock-in; no per-repo fork of `plan-feature.md` / manifest.

## 2. Day-to-day: indie continuous ship

```text
Bug / test đỏ / typo / small patch
        │
        ▼
     /fix

Ý tưởng mới / “nên build X?”
        │
        ▼
  /shape-lite
        │
        └── NEXT: /fix | implement-small | /plan-feature | design-spec | drop
```

### `/fix` — code-loop

**Use when:** bug, failing test, small patch on existing code.

```text
/fix Button submit stays disabled when the form is valid
```

### `/shape-lite` — compact idea shaping

**Use when:** new idea, quick “should we?” — does **not** run GENESIS or force full-stack sections.

```text
/shape-lite Add tag filter on the knowledge list page
```

## 3. Full path: new module / system

### A. `/architecture-plan brainstorming {idea}` — GENESIS

Fills **§0 first**, then only on-layer AGENTS sections → architecture → roadmap → judge.

### B. `/plan-feature {desc}`

Conditional checklist from active layers (no forced “Database migration needs” when database=off).

### C. `/dev-module {name}`

Execute approved module plan with layer-aware workers.

## 10. Porting to another repo

**Do not** hand-edit `plan-feature.md`, `agent-matrix.json`, or `skills-manifest.v2.json` per product.

1. Copy `.cursor/` and `AGENTS.md` (optional `docs/` scaffolding).
2. Fill **`AGENTS.md §0`** — profile + layers on/off (2 minutes).
3. Fill §1–§3 for layers that are on; optional sections → `N/A — layer off` when off.
4. ```bash
   python3 .cursor/context/profile-sync.py --from-agents
   python3 .cursor/context/memory-loader.py --sync
   ```
5. Optional: tighten `worker-scopes.json` globs to §3; set `projectProtectedGlobs`.
6. Day path: `/fix` · `/shape-lite` · `/plan-feature` only when structural.

Detect suggestion (then copy into §0 and re-sync):

```bash
python3 .cursor/context/profile-sync.py --detect
```

Rationale: [docs/vision/project-profile-layers.md](./docs/vision/project-profile-layers.md).

## 11. Troubleshooting

| Symptom | Cause / fix |
|---|---|
| Plan still has migrations on FE-only | §0 database still on, or profile-sync not run |
| `database-worker` on a UI bug | Re-run profile-sync; matrix filters via active-layers |
| AGENTS_INCOMPLETE on product plan | Fill §0 + required on-layer §1–§3 |
| Used `/dev-module` for one-line bug | Prefer `/fix` |
| Frontend blocked (full path) | DESIGN-GATE — need contract/sketch when frontend=on |

---

**In short:** Fill **§0** → `profile-sync` → daily `/fix` + `/shape-lite`. Plans never force off-layer full-stack content.
